A module-level docstring explaining what it's for (see the style of gatekeeper.py /
gauntlet.py's docstrings — plain prose, no marketing tone, explain the constraint not

Public surface:

TEST_TIMEOUT_S = 600

def run_tester_for_job(conn, job_id: int, cfg: dict[str, Any]) -> dict[str, Any]:

`run_tester_for_job` behaviour, in order:
1. Read the job row. If missing, or `job["worktree"]` is empty/None or the directory
   doesn't exist on disk, write a skip EVENT (see below for the shape) and return
   `{"ran": False, "passed": False, "reason": "<plain reason>"}`. Do NOT raise.
2. Pick a tester seat: walk `cfg["gauntlet"]["reviewers"]` (same roster the panel
   uses) in order, and take the first seat that is (a) enabled, (b) a DIFFERENT
   `family` from `job["builder_family"]` (guard_no_self_family_testing), and (c)
   `gauntlet.has_runner(row["provider"])`. If none qualifies, write a skip event
   ("no available model from a different family could check whether the tests
   actually ran" — plain English, no jargon) and return
   `{"ran": False, "passed": False, "reason": "no eligible tester seat"}`.
3. Optional but do it: if the chosen seat is metered, reserve money BEFORE running
   the judge, the same pattern `gauntlet._reserve_review_budget` uses but through
   `gatekeeper.spend(conn, seat_id, cents, job_id=job_id, role="test", asked_by="the
   tester")` — note `role="test"` already exists in `gatekeeper.SPEND_ROLES`. Use a
   small flat estimate (e.g. 5 cents), 0 for non-metered seats (still goes through
   the ledger — see gauntlet.py's comment on why 0 still gets recorded). If
   `over_budget(conn, seat_id)` first, or the reservation is refused
   (`gatekeeper.Refused`), treat exactly like "no eligible tester seat" (a skip, try
   no other seat — keep it simple, single attempt is fine for this minimal version).
4. Run `TEST_CMD` with `cwd=Path(job["worktree"])` via `subprocess.run(..., cwd=...,
   capture_output=True, text=True, timeout=TEST_TIMEOUT_S)`. Catch
   `subprocess.TimeoutExpired` and `OSError` — both become `(exit_code=-1, output=<a
   plain description>)`, not a crash.
5. Write the combined stdout+stderr, the command, and the exit code to a log file
   UNDER the worktree (e.g. `<worktree>/chief_output/tester_job_<id>.log`, creating
   `chief_output/` if needed). Then `record_artifact(conn, job_id, "trace",
   path=str(log_file), value=<f"exit code {code}\n" + last TAIL_LINES lines of
   output>, flow="tester", captured_by="harness")`. This MUST happen before the next
   step (the guard requires it to already exist).
6. Build a request/code pair for the judge and call
   `gauntlet.REVIEWERS[tester_row["provider"]](request_text, evidence_text,
   tester_row["model"])`. `request_text` should describe the actual job (`job
   ["request"]`) plus an explicit instruction: judge ONLY whether the test run
   actually finished and shows the tests passing (non-zero exit code, or output that
   doesn't show the suite completing, is a FAIL). `evidence_text` is the command run
   + exit code + the captured tail. Catch `gauntlet.ReviewerBroke`,
   `subprocess.TimeoutExpired`, and any other `Exception` from this call — ALL of
   them are a skip (the TOOL failed, not the tests): write a skip event, return
   `{"ran": False, "passed": False, "reason": "<plain reason>"}`. (Note: the test
   suite genuinely FAILING, in step 4, is NOT a tool failure — that's real evidence
   the judge should see and can rightly FAIL on. Only a broken/unreachable JUDGE is a
   skip.)
7. Record the verdict: `record_verdict(conn, job_id, tester_row["id"], verdict=...,
   summary=..., role="tester", reviewed_version=job["head_version"])` (the head_version
   read in step 1, not re-read). Wrap in `try/except GuardViolation` — if the DB
   itself refuses it (shouldn't happen if you did steps 1-3 correctly, but defence in
   depth), treat as a skip with the guard's plain-English text.
8. Write an event on the job (see `_event` shape below) saying the tests were checked
   and confirmed, or checked and something looked wrong — plain English, no verdict
   words.
9. Return `{"ran": True, "passed": verdict == "pass", "reason": summary, "seat":
   tester_row["id"]}`.

A small private `_event(conn, job, kind, detail)` helper mirroring the shape used in
gatekeeper.py's `_note` / executor.py's `_event` (INSERT INTO events with job_id,
seat_id, lane, model, family, kind, detail) — use `job["builder_seat"]`'s seat row for
the seat/model/family columns when the event isn't clearly about a different seat (the
skip-before-picking-a-tester case has no tester seat yet, so attribute it to the
builder's own seat row, same as gatekeeper.py's `_note` does). Skips are kind='skipped'.
A genuine pass/fail verdict event is kind='verdict' (pass) or kind='error' (fail) —
match gauntlet.py's `_review_one` convention.

Never raise out of `run_tester_for_job`. Every exit path returns the dict.

```python
def _after_certification(conn, job_id: int, cfg: dict[str, Any]) -> None:
    """Once the panel certifies (result.certified), prove the work actually runs and
    ask the one component allowed to ship it. Pulled out of run_job so it can be
    exercised directly against a job already parked at 'done'.
    """
    import tester
    outcome = tester.run_tester_for_job(conn, job_id, cfg)
    if outcome.get("passed"):
        import gatekeeper
        try:
            answer = gatekeeper.handle(
                {"verb": "merge", "job_id": job_id, "asked_by": "the panel"},
                db_path=DB_PATH)
        except Exception as exc:  # noqa: BLE001 — asking must never crash the worker
            answer = {"ok": False, "error": "something went wrong asking to merge this"}
        if not answer.get("ok"):
            # gatekeeper.handle already wrote its own refusal onto the job's events
            # (gatekeeper.py rule 3) — put the same plain-English reason where the
            # voice/UI actually reads current status.
            set_status(conn, job_id, "done",
                       spoken_summary=str(answer.get("error") or
                                          "the gatekeeper said no")[:200])
        # else: gatekeeper.merge already moved status to 'shipped'.
    elif outcome.get("ran"):
        set_status(conn, job_id, "done",
                   spoken_summary="Checked and certified, but the automated tests "
                                  f"didn't confirm it runs: "
                                  f"{str(outcome.get('reason') or '')[:160]}")
    # else: the tester couldn't run at all — it already left its own skip event; the
    # job simply stays exactly where the panel left it.
```

And in `run_job` step 5:
```python
if cfg is not None:
    import gauntlet
    panel = gauntlet.run_panel(conn, job_id, job["request"], result, version, cfg,
                               db_path=DB_PATH)
    if panel.certified:
        _after_certification(conn, job_id, cfg)
```
