## What got done

### #10 — the full review panel (pushed, `3517c17`)

Before: dispatch ran ONE reviewer, and "at least two different model families must
agree" lived in a config file that nothing enforced.

Now: reviewers run **in parallel against one frozen version**; the **database itself**
refuses to complete a job unless enough genuinely different model families passed *that
exact version*; a reviewer that was capped out, switched off or crashed is **written
down as not having participated** and can never count as approval; money is reserved
before a paid reviewer is called; and if the panel can't reach the floor, the work waits.

Proved live twice: the free local model built something, Claude and GPT reviewed the
same version side by side, the job completed, Grok logged as sitting out.

Reviewers found eight real defects in it, including one that would have certified work
nobody reviewed and one where a broken login would have permanently condemned good code.
All fixed with regression tests.

### #11 — the gatekeeper (built, NOT pushed, `66ad8a2`)

`harness/gatekeeper.py`. Three verbs — merge, deploy, spend — and no fourth. Agents ask;
it re-reads the record itself rather than believing the request. `dispatch.ship()`, which
was one import away from every agent, is gone.

Reviewers hit it hard and found more, all fixed — most seriously that **merge merged
whatever the branch currently pointed at, never checking it was the code that had been
reviewed**. Build v1, get it approved, push v2, ask to merge: v2 went in. It now refuses
unless the branch tip *is* the reviewed version, and the record decides before git is
touched at all.

### Migration 007 — two holes under #10, found after it was pushed

1. **A job with no requirements had no requirements to fail.** Both completion guards
   only fired when the requirement counts were above zero, and they default to zero. A
   job created outside dispatch went straight to done with no reviews at all.
2. **The builder's own family counted toward "different minds."** A GPT seat could build
   it, a GPT seat could pass it, and that counted as one of the two required families.
   Same-family review is still *allowed* (deliberate earlier decision, and banning it
   outright would deadlock a Claude-built job) — it just no longer counts toward
   diversity.

### The "hole in the wall"

The gatekeeper is a **door**. Every agent still runs as Neill and can open the database
file directly, so a determined process could walk around it. The door is real; the wall
isn't built. Three things close it, in order of value:

1. **Branch protection** (above) — the only wall not on this machine.
2. **Credentials off the machine** — the real defence against a prompt-injected agent.
3. **A separate macOS account for the agents**, owning nothing, reaching the records only
   through the gatekeeper. ~1 hour, needs his password once. **Not worth doing until 1
   and 2 are done.**

This limitation is stated plainly in `gatekeeper.py`'s own docstring, on purpose — a
gatekeeper everyone believes in but that doesn't hold is worse than none.
